# App icon: 04 Log, final

Canvas: https://claude.ai/artifact/ScTE29QmxCwxJxfRdnrNPd, on the "Final" board (private until shared from its Share
menu). Everything here is generated by `export.sh` from the geometry in `gen.py`, so edit `gen.py` and rerun it:

    design/logo/final/export.sh

It needs uv (through mise) and Xcode 26 or later, for swiftc, iconutil, actool and Icon Composer's ictool.

## Files

| Path | What |
|---|---|
| `gen.py` | The geometry and colours: one master and one small cut, four layers each (trail, rings, head bar, head). |
| `svg/icon-{light,dark}.svg` | 1024 masters on the Big Sur grid: an 824 body at 100 with continuous corners. |
| `svg/icon-{light,dark}-small.svg` | The cut used below 60px. The rings become dots and the strokes thicken. |
| `svg/mark-*.svg` | The bare mark, with no body. |
| `png/{light,dark}/icon_*.png` | Every macOS size: 16, 32, 128, 256 and 512, each @1x and @2x, in iconset naming. Pixel sizes below 60 (16, 16@2x, 32) use the small cut. |
| `AppIcon.icns` | The light PNGs as a classic icon file. |
| `AppIcon.icon/` | The Icon Composer document the app ships. It's copied to `app/Tasks/AppIcon.icon`. |
| `system/*.png` | What macOS 26 and later draw from `AppIcon.icon` in each appearance: Default, Dark, Tinted, and Clear (each light and dark). Rendered by ictool. |
| `render.swift` | SVG to PNG through AppKit, so no extra tools are needed. |

## Appearances

- **Light and dark:** the background gradient and every layer's colour are set per appearance in `icon.json`.
- **Tinted:** the system reads each layer's lightness. With the default colours the dark head bar disappeared and the
  history came out brighter than the head. So tinted sets its own greys: the head and its bar are white, the rings
  `#B8B8B8` and the trail `#7A7A7A`.
- **Clear:** Icon Composer has no clear key. ictool rejected every key it was given except `dark` and `tinted`. Clear
  takes the tinted values, which keeps the same order.
- **Glass and translucency:** both are off and the shadow is neutral at 30%, which keeps the icon quiet.

## Left out

- **The small cut in the app.** An `.icon` has no per-size variants. When `AppIcon.icon` and an `AppIcon.appiconset`
  both exist, actool uses the `.icon` and ignores the appiconset; I checked this by comparing actool's `.icns` output
  for both setups. So on macOS 26 and later the system draws 16 and 32 from the master, and `AppIcon.icns` for macOS
  14 and 15 is rendered from it too. That version is softer at 16 than the hand-tuned cut but stays readable, as the
  optical check on the canvas shows. The cut ships in `png/` and `AppIcon.icns` here for anything that takes plain
  files. The app's empty `AppIcon.appiconset` was removed, because it would only be shadowed.
- **A sidebar header or About panel glyph.** The app doesn't draw an app glyph in either place: the About panel is the
  standard one and takes the app icon by itself. Nothing to change.

## Polish over the picked direction

The shapes are the ones the user picked. Only the following changed:

- The gaps between node edges are equal (88), and the mark is centred on the body both ways.
- The older bars are a step brighter: light `#A9ACAF`, dark `#6D7072`.
- In the small cut, the dots take the ring colour, so they hold at 16.
- Every shape is a filled outline with no strokes, so every renderer, Icon Composer included, draws the same thing.
