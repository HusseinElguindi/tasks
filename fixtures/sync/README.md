# Sync fixtures

The wire contract for `POST /v1/sync` (SPEC §5–§6), shared by the server and the macOS client.
Generated by `server/scripts/make-fixtures.mjs` (`cd server && pnpm fixtures`); don't edit by hand.
The server tests (`server/test/fixtures.test.ts`) replay every file and require the server's
response to match byte for byte.

## Files

| File | What |
|------|------|
| `NN-*.json` | One request/response pair each. `01`–`05` are the SPEC §5 worked examples (with `b`/`c` follow-ups); `06`–`10` cover the remaining rows of the error and HTTP tables; `11` is an op with the optional `actor` and `batch` keys; `12` a heading (`kind`) and a list's `notes`; `13` `kind` rejected on an update. |
| `hash-vectors.json` | The opA/opB chain hashes, with the exact stored op text that was hashed. |
| `log-2345.jsonl` | The 2,345-entry log behind example 2, one server entry per line, in the client's `log.jsonl` format. |

## Pair format

```jsonc
{
  "name": "01-push",
  "spec": "§5 worked example 1",
  "description": "…",
  "setup": { "log": [op, …] },           // or { "logFile": "log-2345.jsonl" }: the log before the request
  "request":  { "method": "POST", "path": "/v1/sync", "headers": { … }, "body": { "from": 0, "base": null, "ops": [ … ] } },
  "response": { "status": 200, "headers": { … }, "body": { "entries": [ … ], "head": 2, "more": false } }
}
```

- `request.body` is absent when there is no body (`10-method-not-allowed`).
- `response.headers` lists the headers that matter. `Content-Encoding` appears only when the request sent `Accept-Encoding`;
  `URLSession` decodes it transparently, so a client test can ignore it.
- The bearer token is `test-token`; `04-bad-token` sends `wrong-token`.
- `received` is server time. Every fixture uses `1761811261234`, the value in the SPEC examples; a real server returns its clock.
- Error `message`s are for logs only. Clients branch on `status` and `error` (and `index`/`field` for `invalid_op`).
- Ids elided in the SPEC (`7d1e…`, `8e2f…` in example 3) and the example 2 filler (seq 2–2344: title edits to opB's
  task) are fixed, arbitrary UUIDs. Example 5's "different entry 1" is a task.create titled "Buy bread".
